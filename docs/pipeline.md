# Pipeline: prototype -> codegen -> Playwright

One command (and one MCP tool) runs the whole chain and reports a result per flow.

```
opendesigner pipeline -doc "Shop" -out ./app
```

Stages, in order. A failing stage stops the chain and the later ones are reported `skipped`.

1. **prototype**: the flow graph is analysed (`flow check`). Problems are counted per
   flow in the report but do not block; `flow check` stays the CI gate.
2. **codegen**: the react project is written (as `opendesigner export`), including
   `tests/flows.spec.ts`.
3. **install**: `npm install` and `npx playwright install chromium` in the project.
4. **playwright**: `npx playwright test --reporter=json`. The JSON is folded back into
   flows through the `Flow: <name>` describe titles the generated tests use.

Per flow: `passed` (some test passed, none failed), `failed` (any test failed) or
`skipped` (nothing ran). Tests that the generator emitted as `test.fixme` (missing
`code.route` or locator) count as skipped, never as passed. The report is Markdown by
default, `-format json` for machines.

Options: `-workspace`, `-doc`, `-flow`, `-out` (default: a temp directory), `-force`,
`-skip-install`, `-no-tests` (stop after codegen), `-format`. Exit code 0 when green,
1 when a stage or test failed, 2 for bad usage.

MCP: `run_pipeline` (`outDir`, `flowId`, `force`, `skipInstall`, `noTests`) returns the
same report; the project is generated by the server (so images resolve), and failures
are part of the report (`ok: false`), not tool errors.

## Limits

- Needs node/npm, a network on the first run and a Playwright Chromium; the unit tests
  use a fake runner, so the real install-and-run path was not exercised here.
- Two flows with the same name share one Playwright describe title, so their test
  results are merged under both.
- Only the react target is run; the leptos target also has the tests but needs `trunk`.
